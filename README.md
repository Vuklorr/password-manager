# Guard — менеджер паролей

Java 21, Spring Boot 3.5.16, Spring Security, PostgreSQL 17, Flyway и Docker Compose. Веб-интерфейс на русском языке и расширение Chromium Manifest V3 для Chrome/Edge. Сборщик JavaScript не требуется.

**Статус:** учебный прототип без независимого аудита. Пока используйте тестовые учётные данные; проект не рекомендуется как основное хранилище настоящих паролей. Подробности — в [SECURITY.md](SECURITY.md).

## Запуск

Нужны Docker Desktop с запущенным Engine и Docker Compose v2.

```powershell
Copy-Item .env.example .env
# Замените POSTGRES_PASSWORD в .env на длинный случайный пароль БД.
docker compose up --build -d
```

Откройте <http://localhost:8080>. Создайте хранилище, задайте мастер-пароль длиной минимум 14 символов, скачайте аварийный комплект и сохраните его отдельно. Секретный ключ показывается только при регистрации. Для следующих входов нужны **мастер-пароль и секретный ключ**. Сервер не может их восстановить.

Compose открывает приложение только на `127.0.0.1`. База не публикует порт; данные сохраняются в Docker volume. Обычная остановка: `docker compose down`. Не добавляйте `-v`, если хотите сохранить данные.

## Подключение к PostgreSQL

Из контейнера приложения база уже доступна по `jdbc:postgresql://db:5432/vault`. Имя `db` работает внутри сети Compose.

Для SQL-консоли на компьютере не нужно публиковать порт БД:

```powershell
docker compose exec db psql -U vault -d vault
```

Примеры запросов:

```sql
\dt
SELECT id, email, created_at FROM vault_user;
SELECT id, user_id, revision, updated_at FROM vault_entry;
\q
```

Поля `iv` и `ciphertext` в `vault_entry` содержат зашифрованную запись. Открытых столбцов с логином или паролем сайта нет. `vault_user.verifier` — хеш производного ключа авторизации; это тоже чувствительные данные.

Для подключения через DBeaver, DataGrip, IntelliJ IDEA или pgAdmin включите дополнительный Compose-файл:

```powershell
docker compose -f compose.yaml -f compose.db-tools.yaml up --build -d
```

Параметры подключения:

- Тип подключения: PostgreSQL.
- Host: `127.0.0.1`.
- Port: `5433` (в контейнере остаётся `5432`).
- Database: `vault`.
- User: `vault`.
- Password: значение `POSTGRES_PASSWORD` из вашего локального `.env`.
- JDBC URL: `jdbc:postgresql://127.0.0.1:5433/vault`.

Порт привязан только к loopback, доступ с других компьютеров не включается. SSL для этого локального соединения не настроен. Не переносите эти параметры на публичное сетевое соединение без TLS. Для остановки этой конфигурации используйте `docker compose -f compose.yaml -f compose.db-tools.yaml down`.

`POSTGRES_PASSWORD` применяется при первом создании базы. Если volume уже существует, простое изменение `.env` не меняет пароль существующего пользователя PostgreSQL. Не удаляйте volume ради смены пароля: выполните `\password vault` в psql, задайте новый пароль и затем обновите `.env` и пересоздайте контейнер приложения.

## Выход и автовыход

Кнопка **«Выход»** очищает ключ и данные текущего сеанса на клиенте и отправляет серверу запрос отзыва токена. **Автовыход** происходит после 5 минут бездействия. Веб-приложение учитывает нажатия клавиш и действия указателем; в расширении срок продлевается при запросе заполнения. У серверного токена также есть абсолютный срок 30 минут.

Сеансы веб-приложения и расширения отдельные: выход из одного не завершает другой. Вкладки веб-приложения тоже получают отдельные сеансы. При недоступном сервере клиент всё равно очищает свои данные, но отзыв токена может не дойти до сервера; тогда токен остаётся действителен до истечения его срока. Таймеры браузера могут задерживаться во время сна компьютера или приостановки вкладки.

## Нужен ли сервер

Покупать сервер для локального использования не требуется. Достаточно своего компьютера с Docker: приложение и PostgreSQL работают на нём, пока компьютер и контейнеры запущены. Во время сна или выключения компьютера этот экземпляр недоступен. Офлайн-клиент и синхронизация автономного хранилища пока не реализованы.

Для доступа с разных устройств в любое время нужен постоянно работающий узел: домашний компьютер, NAS/мини-ПК или арендованный VPS. VPS не обязателен. Развёртывание в интернете потребует HTTPS, настройки доступа, обновлений и резервного копирования. Для домашнего узла можно организовать доступ через VPN, но это тоже отдельная настройка. В текущем расширении адрес сервера зафиксирован как `http://localhost:8080`; для удалённого экземпляра его нужно изменить вместе с `host_permissions` и ссылкой в `extension/popup.html`.

Постоянно включённый сервер сам по себе не обеспечивает сохранность данных: нужны резервные копии PostgreSQL и проверенная процедура восстановления. Аварийный секретный ключ и мастер-пароль храните отдельно. Потеря любого из них означает потерю доступа к зашифрованным данным.

## Автозаполнение

1. Откройте `chrome://extensions` или `edge://extensions`.
2. Включите режим разработчика, нажмите «Загрузить распакованное расширение», выберите каталог `extension` этого проекта.
3. Закрепите расширение, откройте его и войдите теми же email, мастер-паролем и секретным ключом.
4. Перейдите на сохранённый HTTPS-сайт. Возле подходящей формы появится кнопка Guard. После входа в расширение можно обновить страницу или сфокусировать поле входа, чтобы предложение появилось.
5. Нажмите кнопку для заполнения. Либо выберите запись в окне расширения. Выбор для другого origin вернёт: **«Данный домен не соответствует сохранённому, ОШИБКА»**.

`mail.gOOgle.com` и `mail.google.com` — один домен: DNS не различает регистр. Реальные примеры подделки: `mail.go0gle.com`, `mail.google.com.attacker.org`, `mail.gоogle.com` с кириллической `о`.

Сравнивается **origin: HTTPS + точный hostname + порт**. Путь страницы не участвует. `accounts.google.com`, `mail.google.com` и `google.com` — разные сайты, разрешение между ними не наследуется. У Gmail вход обычно происходит на `accounts.google.com`; сохраняйте адрес фактической формы входа. Порт 443 считается стандартным HTTPS-портом. Другой порт требует отдельной записи.

Расширение поддерживает обычные формы входа с одним видимым полем пароля, методом POST и отправкой на тот же origin. Для многошагового входа поддерживаются шаг с одним полем `autocomplete="username"` и отдельный шаг с одним полем пароля; на каждом шаге требуется отдельный клик. Iframe, нестандартные Web Components, неоднозначные формы, несколько полей пароля и внешние action/formaction блокируются. Совместимость со всеми формами конкретных сервисов не гарантируется. На неподдерживаемых сайтах можно вручную скопировать логин/пароль из веб-приложения, проверив адрес. Копирование не выполняет проверку назначения.

Установленные разрешения: content script на HTTPS-страницах для обнаружения форм, `tabs` для повторной проверки адреса, `activeTab` для выбранной вкладки, `storage` для памяти сеанса, `alarms` для автовыхода. Расширение общается только с `http://localhost:8080`. Закрытые или недоступные формы вызывают отказ, а не обход проверки.

## Генерация и просмотр паролей

- В редакторе выберите алфавит и точную длину от 6 до 128 символов (по умолчанию 24). Алфавиты включают 10 цифр, 26 строчных латинских букв, 62 латинские буквы и цифры либо 95 печатных символов ASCII (включая пробел). Генератор использует `crypto.getRandomValues` и исключает пароли, которые уже есть в вашем хранилище.
- После генерации сразу отображается `L × log₂ A` в битах, где `L` — длина, а `A` — размер алфавита генератора. Для собственного или ранее сохранённого пароля нажмите **«Посчитать энтропию»**. Если алфавит генерации неизвестен, приложение складывает размеры присутствующих групп ASCII (цифры, строчные, заглавные, пробел и знаки) и учитывает каждый уникальный символ вне ASCII. Для введённого вручную пароля результат оценивает пространство перебора при случайном выборе символов.
- **«Показать пароль»** в редакторе и **«Копировать пароль»** в списке запрашивают секретный ключ из аварийного комплекта. Проверка выполняется в браузере. Она защищает от случайного просмотра через интерфейс открытого хранилища. Расширение заполняет подходящую форму на сохранённом сайте после разблокировки расширения.

## Что реализовано

- Регистрация, вход, отдельное хранилище каждого пользователя.
- Добавление, просмотр списка, редактирование и удаление записей; поиск по расшифрованным данным в браузере.
- Шифрование до отправки, секретный ключ 256 бит при регистрации, аварийный комплект.
- Автовыход через 5 минут бездействия. Сессия сервера имеет абсолютный срок 30 минут; выход отправляет запрос её отзыва.
- Ограничение запросов авторизации и попыток входа, optimistic locking для конфликтов редактирования.
- Экспорт зашифрованных записей JSON. Это архив для офлайн-восстановления; кнопка импорта и автоматическое восстановление пока не реализованы. Для полного восстановления сервера сохраняйте также PostgreSQL, включая таблицы аккаунтов и соль.

## Криптография

1. Браузер создаёт случайную соль аккаунта (32 байта) и отдельный случайный секрет (32 байта, 64 hex-символа).
2. `PBKDF2-HMAC-SHA256(мастер-пароль, соль, 600000)` даёт 256-битный корневой материал.
3. HKDF-SHA256 с секретом в качестве salt выводит **разные** ключи: `guard:v1:auth:<email>` и `guard:v1:vault:<email>`.
4. Ключ авторизации отправляется для входа; сервер хранит только его bcrypt-хеш с cost 12. Он не позволяет вычислить отдельный ключ шифрования, но является повторно используемым удостоверением входа, поэтому требует TLS при сетевом развёртывании.
5. Ключ хранилища используется для AES-256-GCM. Каждое сохранение получает новый случайный IV 96 бит; tag 128 бит. AAD содержит версию формата, нормализованный email и UUID записи — подмена записи между аккаунтами/идентификаторами нарушает аутентификацию.
6. Название, origin, логин, пароль, заметка и алфавит генерации (если известен) шифруются одним JSON. Серверу видны email, соль, UUID, размеры, количество записей и время изменения. Мастер-пароль и секретный ключ не отправляются.

Веб-приложение держит ключи и сессионный токен только в памяти страницы; перезагрузка требует повторного входа. Расширение хранит ключ шифрования и токен в `chrome.storage.session`, доступном только доверенным контекстам расширения. Это память браузера, а не `local`/`sync`: переживает остановку service worker, очищается при перезапуске браузера и при выходе. Исходные мастер-пароль, секрет и производный ключ авторизации там не сохраняются. Удаление ссылок на JS-строки не гарантирует немедленное стирание физической памяти.

Рекомендации: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [OWASP Cryptographic Storage](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html), [Chrome session storage](https://developer.chrome.com/docs/extensions/reference/api/storage).

## Границы защиты

Это учебный проект с работающим основным сценарием, без независимого аудита. Точное совпадение origin защищает от поддельных адресов, но не от взломанного настоящего сайта, вредоносного расширения, malware, кражи памяти/буфера обмена или скомпрометированного сервера, раздающего изменённый JavaScript. После заполнения настоящий сайт получает пароль и может читать его из своей формы. Сертификаты проверяет браузер; расширение не обходит ошибки TLS и не ведёт рейтинг репутации сайтов. Для простоты все IDN/Punycode-домены запрещены, даже легитимные.

Для публичного использования нужен HTTPS reverse proxy с доверенным сертификатом, закрытым прямым доступом к приложению, ограничением размера тела (64 KiB) и rate limiting. В `extension/background.js` замените `BASE` на точный HTTPS-адрес, а в `manifest.json` — соответствующий `host_permissions`. Не открывайте локальный HTTP-порт наружу. Фильтр размера по Content-Length является дополнительной проверкой; proxy должен ограничивать также chunked-запросы.

Ограничитель попыток хранится в памяти одного процесса и сбрасывается после рестарта. Для нескольких экземпляров нужен общий Redis/proxy limiter. Нет подтверждения email, TOTP/WebAuthn 2FA, смены мастер-пароля/секрета, сброса доступа, совместного доступа или автоматической проверки утечек. 2FA можно добавить отдельно; отдельный секретный ключ сам по себе не является полноценным одноразовым вторым фактором.

## Разработка и проверки

```powershell
mvn test
node --test tests/*.test.js
mvn package
```

Backend-тесты поднимают Spring Boot/Security/Flyway с H2 в режиме PostgreSQL: регистрация, вход/выход, истечение сессии, изоляция аккаунтов, валидация, конфликты версий и ограничение попыток. Это не замена интеграционной проверке на настоящем PostgreSQL.

Node-тесты проверяют AES-GCM, изменение IV, подмену шифротекста, связь с UUID/email, неправильный мастер-пароль/секрет, генератор и фишинговые URL.

Дополнительная браузерная проверка (только тестовые данные): после `mvn test` запустите `./scripts/start-smoke-server.ps1` в отдельном терминале. Затем `npm install`, `npx playwright install chromium` и `npm run test:browser`. Можно задать `CHROME_PATH` для установленного Chrome вместо скачивания Chromium. Тест проверяет регистрацию, CRUD, повторный вход, экспорт, мобильный экран и проверки формы в настоящем браузере; транспорт API расширения имитируется. Установка расширения и работа на реальных внешних сайтах проверяются отдельно вручную. Тестовый H2-сервер слушает порт 8080 и не должен работать одновременно с основным приложением.

Общие клиентские модули находятся в `src/main/resources/static/lib`. После их изменения выполните:

```powershell
./scripts/sync-extension.ps1
```

Тест сравнивает копии в `extension/lib`, чтобы браузер и расширение использовали одинаковую криптографию и правила origin.

Для запуска Java вне Docker задайте `DB_URL`, `DB_USER`, `DB_PASSWORD` для доступного PostgreSQL и выполните `mvn spring-boot:run`. Из контейнерной сети база доступна как `db:5432`, из Windows это имя недоступно; при необходимости опубликуйте порт БД только на loopback отдельным override-файлом Compose.

## API

Все тела JSON. Операции хранилища требуют `Authorization: Bearer <token>`. Cookie-авторизация и CORS не включены.

- `POST /api/auth/params` — `{email}`, возвращает соль и параметры KDF; для неизвестного аккаунта выдаёт случайную соль того же формата.
- `POST /api/auth/register` — `{email, salt, authKey}`, возвращает `{token, expiresAt}`.
- `POST /api/auth/login` — `{email, authKey}`, возвращает сессию.
- `POST /api/auth/logout` — отзывает текущий токен.
- `GET /api/entries` — список `{id, iv, ciphertext, revision}`.
- `PUT /api/entries/{uuid}` — `{iv, ciphertext, revision}`; 0 для новой записи, текущая версия для обновления.
- `DELETE /api/entries/{uuid}` — удаляет только собственную запись.
- `GET /api/health` — состояние процесса, без секретов.
